# SEED-DOCS — наполнение базы знаний (отдельная команда, после SEED)

Цель — уровень 2 `workspace/docs/` (`knowledgebase/`, для `services` — `contracts/`) по фактическому коду. Большая
задача: делать по областям, по одной за запуск (аргумент — область: «бронирования», «auth», «события»). Эталон —
`agent-workspace-template/example/workspace/docs/`.

1. Если в репо уже есть доки (`docs/`, `*.md`) — сначала индексировать их в `workspace/docs/README.md` ссылками,
   **не дублировать**. Генерировать только то, чего нет. При `team: team` — здесь копии только того, что нужно
   агенту; доки команды первичны.
2. `knowledgebase/NN-тема.md`: правила в таблице с UC-id, «источник истины — код», дата и коммит сверки,
   явные расхождения со старыми спеками. Не писать сигнатуры и перечни полей — это doc-комментарий в коде.
3. `contracts/` (services): события/REST между сервисами — схема + фикстура из реального кода (DTO, сериализаторы,
   тесты).
4. Сырьё в `docs/raw/` — выжимка в уровень 2 с сохранением промпта рядом (`prompt.md`).
5. Обновить матрицу «что изменилось → куда писать» в `workspace/docs/README.md`. `check/links.sh` зелёный.
Ничего не запускать; читать код и тесты. Не выдумывать поведение — при неясности пометить «⚠️ не подтверждено кодом».
