# SEED-DOCS — наполнение базы знаний (отдельная команда, после SEED)

Цель — `workspace/docs/{knowledgebase,contracts,features}` по фактическому коду. Большая задача: делать по областям,
по одной за запуск (аргумент — область: «бронирования», «auth», «события»). Эталон — `agent-workspace-template/example/workspace/docs/`.

1. Если в репо уже есть доки (`docs/`, `*.md`) — сначала индексировать их в `workspace/docs/README.md` ссылками,
   **не дублировать**. Генерировать только то, чего нет.
2. `knowledgebase/NN-тема.md`: правила в таблице с UC-id, «источник истины — код», дата и коммит сверки,
   явные расхождения со старыми спеками.
3. `contracts/`: события/REST между сервисами — схема + фикстура из реального кода (DTO, сериализаторы, тесты).
4. `features/<Feature>/`: если есть сырьё в `docs/raw/` — выжимка по конвейеру raw → features с сохранением промпта.
5. Обновить матрицу «что изменилось → куда писать» в `workspace/docs/README.md`. `check/links.sh` зелёный.
Ничего не запускать; читать код и тесты. Не выдумывать поведение — при неясности пометить «⚠️ не подтверждено кодом».
