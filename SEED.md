# SEED — засев слоя агента в проекте (промпт для агента)

Ты работаешь из корня проекта, в котором лежат репозитории кода (или пока ничего, кроме концепт-доков) и клон
`agent-workspace-template/`. Скелет уже развёрнут `init.sh` по профилю (`project.yaml: profile`; если нет — запусти
`agent-workspace-template/init.sh .`, он спросит). Задача — заполнить слой: карта, манифест, правила, `AGENTS.md`
репо. Эталон глубины и тона — `agent-workspace-template/example/` (проект Bookly: `kind: services`, `team`, remote-трекер;
читается только на фазе засева и по явной просьбе): читай его файлы **перед** тем, как писать соответствующие файлы
проекта. **Профиль читай из `project.yaml: profile`** — он определяет, какие разделы и правила уместны (например,
при `team: team` инструкции репо — черновики для команды, без ссылок на этот слой; при `tracker: remote` —
постановки без локальных путей).

**Не генерируй базу знаний (`workspace/docs/knowledgebase` и уровень 2) — это отдельная команда (`SEED-DOCS.md`).**

Сначала определи путь: в корне есть папки с `.git` → **A (есть код)**; нет → **B (greenfield)**.

## A. Есть репозитории
1. **Инвентаризация.** Для каждой папки в корне с `.git`: README, Makefile/Taskfile/Cargo.toml/package.json, compose,
   `.env*.example`, существующие `CLAUDE.md`/`AGENTS.md`/`docs/`, роутинг, способ auth между сервисами. Ничего не
   запускай — только читай. Зафиксируй: стек и версии, базовую ветку (`git -C <repo> symbolic-ref
   refs/remotes/origin/HEAD`), формат коммитов (`git -C <repo> log --oneline -30`), порты, адреса, **команды
   качества** (test/lint/bench/smoke — как их реально запускает команда).
2. **`project.yaml`** — `repos[]` с `commands` (только то, что нашёл; не угадывать), для `services` — `run.team`,
   `ports`. Профиль не трогать (его задаёт `init.sh`). В корневой `.ignore` — строка `!/<путь>/` на каждый репо
   (проверка — `check/searchignore.sh`).
3. **`AGENTS.md` корня** — по `example/AGENTS.md` и правилам `PRINCIPLES.md`: тонкий (≤ ~100 строк): о продукте и
   стек (из README), маршрутизация уже есть, карта проекта — строка на репо. Никаких таблиц модулей и архитектуры —
   это `<repo>/AGENTS.md`. Существующие корневые `CLAUDE.md`/карты — источник, перенеси и удали дубли.
4. **`AGENTS.md` каждого репо** — черновик: `agent-workspace-template/init.sh render repo-template/AGENTS.md`
   (учитывает профиль) + `example/repos/*/AGENTS.md`; техдоки — `repo-template/docs/README.md` (карта «код → техдок»
   с триггерами) и гейт `repo-template/scripts/check-docs.sh`. Если в репо уже есть актуальный `CLAUDE.md`/`AGENTS.md`
   — не переписывай, предложи только `CLAUDE.md`=`@AGENTS.md` и `gitignore.snippet`. Черновики **показать**;
   при `team: team` — в чужие репо не коммитить, ссылок на этот слой в них нет.
5. **Личное.** `<repo>/CLAUDE.local.md` не заполняй (это делает человек по `repo-template/CLAUDE.local.md.example`);
   проверь `check/gitignore.sh` (не игнорируются — предложи `<repo>/.git/info/exclude`).
6. **Трекер.** `tracker: remote` — `task_prefix` = очередь трекера, `tracker.remote_transport` — чем ходить;
   живые задачи перенести через `/tracker-pull <KEY>` по списку, согласованному с пользователем; старые локальные
   заметки по задачам — в `context/` соответствующих папок. `tracker: local` — задачи из старых заметок заводить
   через `/refine`, показать до записи.
7. **Проверка.** `workspace/bin/check/all.sh` до зелёного. Отчёт: что заполнено, что осталось в `{{…}}`, вопросы.

## B. Greenfield — кода ещё нет
Источник — концепт-доки: `workspace/docs/*.md`, `workspace/docs/raw/`, всё, что пользователь положил в корень
(перенеси в `workspace/docs/`: концепция и этапы — уровень 1 (`CONCEPT.md`, `ROADMAP.md`), сырые обсуждения —
`raw/<тема>/`, решения — `decisions/`, если профиль с ADR). Не выдумывай стек и структуру: чего нет в доках —
`{{…}}` и вопрос.
1. **`project.yaml`** — `repos[]` — **планируемые** репо со `status: stub`, `stack: ""` до решения, `commands`
   пустые. `.ignore` — `!/<путь>/` на планируемые репо.
2. **`AGENTS.md` корня** — о продукте из концепции, стек как «ждёт решения», карта проекта с планируемыми репо,
   правила из концепции (кто решает архитектуру, что уже принято и не переспрашивается, что открыто).
   Текущий этап — не сюда, а в `ROADMAP.md`, «Что делать прямо сейчас».
3. **`workspace/docs/README.md`** — строки для концепт-доков в уровне 1 и матрица «принято решение → куда писать».
4. **Открытые вопросы** концепции — предложить завести задачами (`/tracker-add`, статус `needs-decision`),
   по одной на вопрос; с ADR — критерий готовности «ADR-NNNN accepted», уже принятые решения — ретроспективными
   ADR (`/adr`, статус `proposed`, в контексте «зафиксировано задним числом»); **показать, не заводить без
   подтверждения**.
5. **Проверка.** `workspace/bin/check/all.sh` до зелёного (предупреждения «не склонирован» для stub-репо — норма).
   Отчёт: что заполнено, что решается человеком, вопросы. Когда репо появятся — прогнать путь A для них.

## Существующий проект — что сделать со старым
Путь A плюс перенос. Ничего не удалять, пока проверки не зелёные; старое переносить `git mv` или копированием.
- `init.sh` существующие файлы не перезаписывает и печатает пропущенные — свести их со скелетом руками (обычно
  `CLAUDE.md`, `AGENTS.md`, `.gitignore`): `.gitignore` — белый список из скелета, `git status` показывает **только**
  слой агента, корневой `.ignore` перечисляет все репо.
- Старые корневые `CLAUDE.md`/карты — источник для тонкого `AGENTS.md` корня; архитектура, модули и запуск →
  `<repo>/AGENTS.md`, текущий этап → `ROADMAP.md`/трекер; устаревшие tracked-файлы репо — список в `<repo>/CLAUDE.local.md`.
- Личное: «как я запускаю» и грабли → `<repo>/CLAUDE.local.md`; личные скрипты, прокси-Makefile, хуки → `local/`;
  секреты из `.mcp.json` → `${VAR}` + `local/.env`, засвеченные **перевыпустить**.
- Знания → `workspace/docs/` по уровням индекса; техдоки репо → `<repo>/docs/` под карту `docs/README.md` и гейт
  `scripts/check-docs.sh` (`repo-template/`).
- Трекер → `workspace/tracker/`: задачи получают frontmatter (`id` по `PREFIX-NNNN`; remote — id = ключ трекера),
  раскладываются по `tasks/`, `parked/`, `done/YYYY-MM/`; большие темы — папки-эпики с задачами внутри, задачи с
  контекстом — одноимённые папки. `trk.sh check` до зелёного.
- Репо кода: `AGENTS.md` + `CLAUDE.md` = `@AGENTS.md` (если команда согласна; иначе не трогать и отметить в
  `CLAUDE.local.md`), `gitignore.snippet` в `.gitignore`. В tracked-файлах репо — никаких ссылок на слой агента.
  Старые симлинки и скиллы: проектные — в `.claude/`, остальное удалить.
- `workspace/bin/check/all.sh` зелёный → commit → `agent-workspace-template/sync.sh mark` (маркер для `sync.sh
  pull`/`push`, README шаблона «Обновление слоя»).

## Правила
- Все пути — от корня проекта; в `AGENTS.md` репо — от корня репо.
- Пиши текущее состояние, не историю. Не выдумывай: чего нет в коде/README/доках — оставь `{{…}}` и спроси.
- Инструкция — правила и карта; состояние — `ROADMAP.md`/трекер. Правило — у одного владельца, копия — ссылка.
- Секреты не копировать; в `.mcp.json` — только `${VAR}`.
- Не запускать стек, тесты, установку зависимостей.
