# SEED — засев слоя агента в проекте (промпт для агента)

Ты работаешь из корня проекта, в котором лежат репозитории сервисов (или пока ничего, кроме концепт-доков) и клон
`agent-workspace-template/`. Задача — заполнить слой агента (скелетон уже развёрнут `init.sh`; если нет — запусти
`agent-workspace-template/init.sh <имя> <ПРЕФИКС> . [local|remote]`). Эталон глубины и тона —
`agent-workspace-template/example/` (проект Bookly, `kind: services`; читается только на фазе засева и по явной
просьбе): читай его файлы **перед** тем, как писать соответствующие файлы проекта.

**Не генерируй базу знаний (`workspace/docs/knowledgebase`, `features`, `contracts`) — это отдельная команда
(`SEED-DOCS.md`).** Здесь — структура, карта, манифест, правила, `AGENTS.md` сервисов.

Сначала определи путь: в корне есть папки с `.git` → **A (есть код)**; нет → **B (greenfield)**.

## A. Есть репозитории
1. **Инвентаризация.** Для каждой папки в корне с `.git`: README, Makefile/Taskfile/Cargo.toml/package.json, compose,
   `.env*.example`, существующие `CLAUDE.md`/`AGENTS.md`/`docs/`, роутинг/nginx, способ auth между сервисами.
   Ничего не запускай — только читай. Зафиксируй: стек и версии, базовую ветку
   (`git -C <repo> symbolic-ref refs/remotes/origin/HEAD`), формат коммитов (`git -C <repo> log --oneline -30`),
   порты, адреса, **команды качества** (test/lint/bench/smoke — как их реально запускает команда) и для monorepo —
   модули (крейты/пакеты) и правила зависимостей между ними.
2. **`project.yaml`** — `kind` (`services` — несколько репо; `monorepo` — один репо с модулями; `app` — одно
   приложение), `repos[]` с `commands` (только то, что нашёл; не угадывать) и `modules` (monorepo/app), `run.team`,
   `ports`, `tracker` (спроси режим и префикс удалённого трекера, если не очевидно). Пример — `example/project.yaml`.
   В корневой `.ignore` — строка `!/<путь>/` на каждый сервис (без этого Grep/Glob из корня не видят их код;
   проверка — `check/searchignore.sh`).
3. **`AGENTS.md` корня** — по `example/AGENTS.md`: о продукте (из README), таблица сервисов, для monorepo/app —
   таблица модулей с правилами зависимостей, схема связей, командный запуск, правила. Существующие корневые
   `CLAUDE.md`/карты — источник, перенеси и удали дубли. Устаревшие tracked-файлы инструкций в репо — перечисли явно.
4. **`workspace/docs/dev/README.md`** — командный способ запуска, что нужно на хосте, окружения (без секретов).
5. **`AGENTS.md` каждого сервиса** — черновик по `repo-template/AGENTS.md` и `example/repos/*/AGENTS.md`. Если в репо
   уже есть актуальный `CLAUDE.md`/`AGENTS.md` — не переписывай, предложи только `CLAUDE.md`=`@AGENTS.md` и
   `gitignore.snippet`. Черновики **показать**, в чужие репо не коммитить.
6. **Личное.** Секции `AGENTS.md` «мой способ запуска» и `<сервис>/CLAUDE.local.md` не заполняй (это делает
   человек); если в репо сервисов есть личные файлы (`CLAUDE.local.md`, `Makefile.local`) — проверь
   `check/gitignore.sh` (не игнорируются — предложи `<repo>/.git/info/exclude`).
7. **Трекер.** Есть удалённый трекер — `project.yaml: tracker.mode: remote`, `task_prefix` = его очередь (id задачи =
   ключ трекера), `local_prefix` — для задач без тикета; если `init.sh` запускался в local-режиме — перезапусти его
   с `remote`, чтобы доложить команды трекера. Живые задачи перенести через `/tracker-pull <KEY>` по списку,
   согласованному с пользователем; старые локальные заметки по задачам — в `context/` соответствующих папок.
8. **Проверка.** `workspace/bin/check/all.sh` до зелёного. Отчёт: что заполнено, что осталось в `{{…}}`, вопросы.

## B. Greenfield — кода ещё нет
Источник — концепт-доки: `workspace/docs/*.md`, `workspace/docs/raw/`, всё, что пользователь положил в корень
(перенеси в `workspace/docs/`: концепция и вехи — в `workspace/docs/`, сырые обсуждения — в `raw/<тема>/`, решения —
в `decisions/`). Не выдумывай стек и структуру: чего нет в доках — `{{…}}` и вопрос.
1. **`project.yaml`** — `kind` по замыслу проекта; `repos[]` — **планируемые** репо со `status: stub`, `stack: ""`
   до решения, `commands` пустые, `modules` — если границы уже описаны в концепции; `tracker.mode: local`
   (удалённого трекера обычно нет); `run.team` пустой; `ports: {}`. `.ignore` — `!/<путь>/` на планируемые репо.
2. **`AGENTS.md` корня** — стадия проекта («планирование, кода нет»), лестница чтения через концепт-доки, о продукте
   из концепции, таблица планируемых репо (⬜), границы и связи по замыслу, правила из концепции (кто решает
   архитектуру, что уже принято и не переспрашивается, что открыто).
3. **`workspace/docs/README.md`** — добавить строки для концепт-доков и матрицу «принято решение → куда писать».
   `workspace/docs/dev/README.md` — «кода нет, ждёт решения о стеке», ориентиры из вех.
4. **Открытые вопросы** концепции — предложить завести задачами (`/tracker-add`, статус `needs-decision`),
   по одной на вопрос, критерий готовности — принятое решение; **показать, не заводить без подтверждения**.
5. **Проверка.** `workspace/bin/check/all.sh` до зелёного (предупреждения «не склонирован» для stub-репо — норма).
   Отчёт: что заполнено, что решается человеком, вопросы. Когда репо появятся — прогнать путь A для них.

## Правила
- Все пути — от корня проекта; в `AGENTS.md` сервисов — от корня сервиса.
- Пиши текущее состояние, не историю. Не выдумывай: чего нет в коде/README/доках — оставь `{{…}}` и спроси.
- Секреты не копировать; в `.mcp.json` — только `${VAR}`.
- Не запускать стек, тесты, установку зависимостей.
