# /adr — решение как ADR (`workspace/docs/decisions/`; правила, статусы и кто принимает — README папки)

Аргументы: `<тема | id задачи>` — черновик; `accept ADR-NNNN` — бухгалтерия после принятия; `list`.

## Черновик (`proposed`)
1. **Контекст**: концепция и карта (`AGENTS.md`, `workspace/docs/`), связанные задачи трекера (их «Открытые
   вопросы»), обсуждение `workspace/docs/discussions/…/` и `workspace/docs/raw/` по теме, уже принятые ADR
   (`adr.sh list`) — новый не должен им противоречить молча; противоречит — это замена (`supersedes`), сказать явно.
   Нужны числа (бенчмарк, размер, стоимость) — предложить spike-задачу, не выдумывать.
2. `workspace/bin/docs/adr.sh new <slug> "<название>"` → заполнить по `TEMPLATE-adr.md`: не меньше двух вариантов
   с плюсами/минусами, **рекомендация** в «Решении» с обоснованием, последствия включая плохие, «Открытые вопросы»
   — что нужно от человека. `tasks:` — id задач, породивших вопрос. В задаче — `depends: [ADR-NNNN]`.
3. Показать файл, остановиться. Выбор человека уже явно ясен из обсуждения (условие — README папки) — сразу
   «Принятие» ниже, с датой обсуждения в «Решении».

## Принятие (`accept ADR-NNNN`)
1. `adr.sh accept ADR-NNNN`; убрать раздел «Открытые вопросы» (решённое — в «Решение»/«Последствия»).
2. Отразить решение там, где агент прочитает его первым, по матрице `workspace/docs/README.md`: `AGENTS.md` корня
   или `<repo>/AGENTS.md` (правила, таблицы), концепция, доки уровня 2, техдоки репо. Показать diff.
3. Задачи с `depends: [ADR-NNNN]` — разблокированы (`trk.sh ready`); задачу-вопрос закрыть или перевести в `todo`.
4. Решение заменяет прежний ADR — тот удаляется, когда код и доки переведены (обычно закрытием эпика), по правилу
   README: живые пункты и отвергнутые варианты — в новый, ссылки — на новый.
5. `adr.sh check`, `workspace/bin/check/links.sh`. Коммит — **спросить** (ADR сам по себе не задача; в составе
   задачи — коммитится с ней).
