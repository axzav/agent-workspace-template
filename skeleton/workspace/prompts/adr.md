# /adr — решение как ADR (`workspace/docs/decisions/`, правила — там же в README.md)

Аргументы: `<тема | id задачи>` — черновик; `accept ADR-NNNN` — бухгалтерия после принятия человеком; `list`.

## Черновик (`proposed`)
1. **Контекст**: концепция/карта (`AGENTS.md`, `workspace/docs/`), связанные задачи трекера (их «Открытые вопросы»),
   `raw/` по теме, уже принятые ADR (`adr.sh list`) — новый не должен им противоречить молча; противоречит —
   это замена (`supersedes`), сказать явно. Нужны числа (бенчмарк, размер, стоимость) — предложить spike-задачу,
   не выдумывать.
2. `workspace/bin/docs/adr.sh new <slug> "<название>"` → заполнить по `TEMPLATE-adr.md`: не меньше двух вариантов
   с плюсами/минусами, **рекомендация** в «Решении» с обоснованием, последствия включая плохие, «Открытые вопросы»
   — что нужно от человека. `tasks:` — id задач, породивших вопрос. В задаче — `depends: [ADR-NNNN]`.
3. **Статус остаётся `proposed`.** Показать файл, остановиться. `accepted` ставит человек.

## Принятие (`accept ADR-NNNN`) — только по явному решению человека
1. `adr.sh accept ADR-NNNN`; убрать раздел «Открытые вопросы» (решённое — в «Решение»/«Последствия»).
2. Отразить решение там, где агент прочитает его первым, по матрице `workspace/docs/README.md`: `AGENTS.md`
   (правила, таблицы), концепция/знания, контракты, `project.yaml` (стек, команды, модули). Показать diff.
3. Задачи с `depends: [ADR-NNNN]` — разблокированы (`trk.sh ready`); задачу-вопрос закрыть или перевести в `todo`.
4. `adr.sh check`, `check/links.sh`. Коммит — **спросить**.
