# /task <KEY> — взять задачу из удалённого трекера в работу (remote-режим; локальная задача — /next-task)

Аргумент — ключ тикета (`{{TASK_PREFIX}}-NNNN`). Без аргумента — спросить ключ и остановиться.

1. **Подтянуть тикет** через транспорт из `project.yaml: tracker.remote_transport`: описание, комментарии, вложения,
   связи (родитель/блокеры).
2. **Локальный файл** в `workspace/tracker/tasks/` (в папке эпика, если родитель уже заведён локально):
   - нет — создать `<KEY>-slug.md` по `TEMPLATE-task.md`: `id`/`remote` = ключ, `created` = дата создания в трекере,
     `remote_synced` = `trk.sh now`; описание разложить по разделам постановки, перенося формулировки, не пересказывая;
   - есть — показать diff описания трекера против файла; расхождения не затирать молча, спросить, кто истина.
   Вложения → `context/` (папка через `trk.sh promote`), комментарии → `comments.md` (только новые,
   `id > last_remote_comment`). `status: in-progress`.
3. **Прочитать контекст**: `INDEX.md` папки (если есть) → постановка → `comments.md` → `implementation.md`; эпик тем же
   порядком; `AGENTS.md`/`CLAUDE.md` затронутого сервиса и его `CLAUDE.local.md`.
4. **Ветка до первой правки**: рабочая копия сервиса чистая (`git -C <repo> status --porcelain` пуст) и на базовой
   ветке → завести feature-ветку от свежей базовой по правилам сервиса. Грязное дерево или чужая ветка —
   остановиться и спросить.
5. **Разведка кода** — одним способом (сам или Explore-подагент, не параллельно). Результат — `implementation.md`
   («Где в системе» → «Как реализуем» → «План» → «Риски»); создать папку, если задача — файл.
6. Показать план и **остановиться для подтверждения**, если задача больше S или есть открытые вопросы.
   Неясная/устаревшая задача → `status: needs-decision`, вопросы в постановку, стоп.
7. Делать. По ходу: журнал в `implementation.md`, находки «стоило бы» — `workspace/tracker/proposals/`.
   Закончил — `/task-done`.
