# /template-sync [status|pull|push] — сверить слой агента с шаблоном и обменяться правками

Скрипт — `agent-workspace-template/sync.sh` (клон шаблона в корне проекта; звать абсолютным путём из корня). Маркер
последней сходимости — `project.yaml: template` (`commit` шаблона, `project_commit` корня). Без аргумента — полный
круг: status → pull → push → проверки → отчёт; с аргументом — только этот шаг и отчёт.

1. **Состояние.** Есть remote — `git -C agent-workspace-template pull --ff-only`. `sync.sh status`: таблица
   DIFF / MISSING / ONLY-IN-PROJECT и счётчики коммитов после маркера. Маркера нет — первая сверка: `sync.sh diff`,
   каждое расхождение разобрать руками по п. 2–3 (это специализация проекта или долг одной из сторон?), затем
   `sync.sh mark`. Рабочие копии шаблона и корня должны быть чистыми, иначе остановиться и спросить.
2. **pull** — `sync.sh pull`. Конфликт (`<<<<<<<`): оставить правило шаблона в формулировке проекта — имя репо,
   термины продукта, числа и пути проекта остаются проектными; маркеры убрать. Когда pull прошёл без конфликтов,
   маркер сдвинут сам; после ручного разбора — `sync.sh mark`.
3. **push** — `sync.sh push`, затем `git -C agent-workspace-template diff`: в `skeleton/` имена репо → плейсхолдер `REPO` в двойных
   фигурных скобках или `<repo>`, термины продукта → общие («пользователь», «сервис», «репо»), проектные числа и пути убрать;
   поведение, зависящее от профиля, — в `{{#if …}}` (ключи — `agent-workspace-template/skeleton/project.yaml`,
   файлы по профилю — `agent-workspace-template/init/profiles.txt`). Конфликт — обычно строка с плейсхолдером:
   перенести правку руками. Правка меняет правило, а не формулировку — строка в `agent-workspace-template/PRINCIPLES.md`.
4. **Файлы без пары.** MISSING — поставить из скелета или вписать в `project.yaml: template.skip`, если проекту не
   нужен; ONLY-IN-PROJECT — общий (добавить в `skeleton/` и `profiles.txt`), проектный (оставить) или мусор (удалить).
   Решение каждого — в отчёте, спорное — спросить.
5. **Проверки.** В проекте — `workspace/bin/check/all.sh`. В шаблоне — self-test: `init.sh` в пустую папку с
   профилем проекта и `sync.sh status` оттуда против неё же — 0 расхождений; `bash -n` правленных скриптов.
6. **Отчёт** 5–10 строк: что подтянуто, что уехало в шаблон, конфликты и решения, файлы без пары. Коммиты — спросить:
   шаблон — отдельный репо (push только по явной просьбе), корень — коммит вне задачи. После коммита корня —
   `sync.sh mark`, чтобы `project_commit` указывал на коммит с правками.
