# /next-task [ID] — взять задачу, сделать и сдать

Здесь — порядок действий. Правила: статусы, файлы задачи и входящие — `workspace/tracker/AGENTS.md`; код и проверки —
`<repo>/AGENTS.md`; коммиты{{#if adr}}, ADR{{/if}}, трение — `AGENTS.md` корня.

## Взять
1. Есть задача `in-progress` (`workspace/bin/tracker/trk.sh board`) — продолжить её, а не брать новую: с места, где
   остановились (журнал `implementation.md`, ветка задачи в репо); готова — сразу к «Сдать»; несколько — спросить.
{{#if tracker=remote}}
   Аргумент — ключ трекера: сначала подтянуть тикет по `workspace/prompts/tracker-pull.md` (файл, `context/`,
   `comments.md`), затем продолжать здесь. Без аргумента — `trk.sh ready`; пусто → сообщить и остановиться.
{{#else}}
   Аргумент-id — брать его. Иначе `trk.sh ready`; пусто → сообщить и остановиться.
{{/if}}
2. Прочитать **ровно столько, сколько нужно плану** (чтение — главный расход контекста):
   - задача: постановка → `comments.md` → `implementation.md` (если есть) → журнал предшественника из «Состава работ»;
{{#if adr}}
   - ADR из `depends` — целиком; эпик и концепция — только если план трогает границу (п. 4);
{{#else}}
   - эпик — только если план трогает границу между модулями или контракт (п. 4);
{{/if}}
   - код: `<repo>/AGENTS.md` (`CLAUDE.local.md` подгружается сам), техдоки — **по карте техдоков репо для темы
     задачи, по одному файлу**; не `cat` пачкой: вывод одного вызова больше ~200 строк уходит в файл и читается дважды;
   - файлы кода — `grep`/`sed -n` по нужным функциям, целиком только те, что будешь править.
   Разведка кода — **одним способом**: либо сам, либо Explore-подагент, не параллельно. Находки, которые понадобятся
   в работе, — в `implementation.md` (M/L; папку и заготовку создаёт `trk.sh promote`), для S — строкой в `comments.md`.
3. Перевести в `in-progress` + `priority: now`. Задача негодна (неясно, устарела, требует решения человека: границы,
   абстракции, целевые цифры) — `needs-decision` с разделом `## Открытые вопросы`, остановиться.
{{#if adr}}
4. **Граница.** План меняет архитектурную границу (состав модулей и их зависимости, контракт между сервисами или
   слоями, формат данных) или противоречит ADR — сначала черновик ADR (`/adr`), показать, дождаться принятия. Без
   принятого ADR границу не двигать.
{{#else}}
4. **Граница.** План меняет границу между модулями или сервисами, контракт или формат данных — остановиться и
   спросить: решение за командой, в коде его не принимать; итог — ссылкой в `implementation.md`.
{{/if}}

## Сделать
5. В репо — ветка от свежей базовой до первой правки (рабочая копия чистая, `git -C <repo> status --porcelain` пуст;
   грязное дерево или чужая ветка — остановиться и спросить); команды и правила — `<repo>/AGENTS.md`, грабли —
   `<repo>/CLAUDE.local.md`. Находки «стоило бы» → `workspace/tracker/proposals/` (формат — «Входящие» в правилах
   трекера). Граница всё же сдвинулась по ходу — п. 4 до сдачи.
6. Проверить по `<repo>/AGENTS.md`: по ходу — тесты и линт только правленного; полный прогон один раз в конце —
   команды качества из `project.yaml` (`workspace/bin/stack/cmd.sh lint|test [repo]`). Красное — сказать как есть,
   с выводом, не сглаживать.
{{#if kind=services}}
   Кросс-сервисные правки — ещё `workspace/bin/stack/healthcheck.sh`.
{{/if}}

## Сдать
7. **Доки** по матрице `workspace/docs/README.md` — править или явно написать «доки: не требуют». Папка задачи —
   одна запись-итог в `implementation.md → Журнал` (что удивило, что чинили); `INDEX.md`, если есть, актуален; у
   задачи без папки итог — в коммите.
{{#if tracker=remote}}
8. **Саммари в трекер** для QA и менеджеров: бизнес-язык, без путей и кода — черновик в `comments.md`, показать, после
   подтверждения отправить (`workspace/prompts/tracker-comment.md`); перевод статуса тикета — предложить, делать по
   подтверждению.
9. **Трекер** — по таблице «Состояния и переходы»: `status: done`, `closed`, `git mv` верхнего уровня в
   `done/YYYY-MM/`; закрытие эпика — по той же таблице. `trk.sh check` зелёный.
{{#else}}
8. **Трекер** — по таблице «Состояния и переходы»: `status: done`, `closed`, `git mv` верхнего уровня в
   `done/YYYY-MM/`; закрытие эпика{{#if team=solo}} и отметка этапа в `workspace/docs/ROADMAP.md`{{/if}} — по той же таблице, без
   вопроса. `trk.sh check` зелёный.
{{/if}}
{{#if commit=auto}}
10. **Коммиты — сразу, без вопроса**, в каждом репо через `git -C` (формат — по правилам репо; корень —
    `{{TASK_PREFIX}}-NNNN: <что сделано>`). Push не делать.
{{#else}}
10. **Коммиты:** показать план по репо (`git -C <repo> …`, формат — по правилам репо; корень —
    `{{TASK_PREFIX}}-NNNN: <что сделано>`). **Спросить перед коммитом.** Push и MR — только по явной просьбе.
{{/if}}
11. Отчёт 5–10 строк: что сделано, что проверено (фактами и числами), что осталось или не покрыто; **трение** —
    файл в `workspace/tracker/friction/` и та же суть полем в отчёте (порог и формат — «Входящие»), или «трение: нет».
