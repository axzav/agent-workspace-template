# /next-task — взять следующую локальную задачу (remote-режим: /task <KEY>)

1. `workspace/bin/tracker/trk.sh ready` — список берущихся задач (todo, без незакрытых depends, не L). Если
   аргумент — id, брать его. Пусто → сообщить и остановиться.
2. Прочитать задачу по порядку из `workspace/tracker/AGENTS.md`: `INDEX.md` → постановка → `comments.md` →
   `implementation.md`; затем эпик тем же порядком и `AGENTS.md` затронутых репо (`repos:`). Разведка кода —
   **одним способом**: либо сам, либо Explore-подагент, не параллельно. Находки разведки, которые понадобятся в
   работе, — в `implementation.md` (создать папку через `trk.sh promote`, если нужна).
3. Перевести в `in-progress` + `priority: now`. Если задача негодна (неясно, устарела) — `needs-decision` с
   разделом `## Открытые вопросы`, остановиться.
4. Сделать. Команды — из `project.yaml: repos[].commands` (`workspace/bin/stack/cmd.sh`); следовать `CLAUDE.local.md`,
   если он есть. Меняется граница между сервисами/модулями или контракт — сначала зафиксировать решение
   (`workspace/docs/`, ADR если проект их ведёт), потом код. Находки → `proposals/`.
5. Проверить: `cmd.sh lint|test [repo]` по затронутым сервисам, `workspace/bin/stack/healthcheck.sh` при кросс-сервисных правках.
   Синхронизация доков по матрице `workspace/docs/README.md` — либо править, либо явно написать «доки: не требуют».
6. Закрыть: `status: done`, `closed` = `trk.sh now`, `git mv` в `done/YYYY-MM/` (внутри эпика — оставить).
   Задача привязана к трекеру — предложить перевести статус и оставить комментарий-резюме (`/tracker-comment`).
   Показать план коммитов по репо (`git -C`),
   **спросить перед коммитом**, push не делать. Отчёт 5–10 строк: что сделано, что проверено, что осталось.
