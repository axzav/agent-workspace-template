# /task-done [KEY] — сдать задачу

Ключ — из аргумента или из текущей feature-ветки сервиса.

1. **Проверки** — `workspace/bin/stack/cmd.sh lint|test|bench [repo]` по затронутым сервисам от дешёвого к дорогому
   (порядок и грабли — `<сервис>/CLAUDE.local.md`; DoD команды — доки сервиса). Кросс-сервисные правки —
   `workspace/bin/stack/healthcheck.sh`. Красное — сказать как есть, с выводом, не сглаживать.
2. **Доки** по матрице `workspace/docs/README.md` — править или явно написать «доки: не требуют».
   `implementation.md → Журнал` — итог; `INDEX.md` — состояние по окружениям.
3. **Саммари в трекер** (remote-режим) для QA/менеджеров: бизнес-язык, без путей и кода — черновик в `comments.md`,
   показать, после подтверждения опубликовать через нормализатор (`workspace/tracker/AGENTS.md`, «Публикация»),
   приписать «→ Отправлен в трекер #<id>». Перевод статуса тикета — предложить, делать по подтверждению.
4. **Локальный трекер**: `status: done`, `closed` = `trk.sh now`; верхний уровень — `git mv` в `done/YYYY-MM/`
   (внутри эпика — оставить).
5. **Коммиты**: показать план по репо (`git -C <repo> …`, формат — по правилам сервиса; корень —
   `{{TASK_PREFIX}}-NNNN: <что сделано>`). **Спросить перед коммитом.** Push и MR — только по явной просьбе.
6. Отчёт 5–10 строк: что сделано, что проверено (фактами), что осталось / не покрыто.
