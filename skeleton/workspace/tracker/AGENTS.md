# tracker/ — задачи и работа над ними

Все пути — от корня проекта. Скрипты: `workspace/bin/tracker/trk.sh` (`board | ready | check | gate | next-id | now |
publish | promote`). Курируемого INDEX нет — дашборд строится из frontmatter.

Два режима (`project.yaml: tracker.mode`):
- **local** — истина по задачам здесь, в файлах; берётся из `ready`, флоу — `/next-task`.
- **remote** — истина в удалённом трекере, здесь **локальное зеркало** постановки плюс то, чего в трекере нет:
  разведка кода, план, журнал, черновики комментариев, материалы. Флоу — `/task <KEY>` → `/task-done`.

## Раскладка
```
tasks/                                  живое
  {{TASK_PREFIX}}-0001-slug.md          задача без контекста — файл
  {{TASK_PREFIX}}-0002-slug/            задача с контекстом — папка
    {{TASK_PREFIX}}-0002-slug.md        постановка (в remote — зеркало описания в трекере)
    INDEX.md                            что здесь лежит и в каком порядке читать; состояние по окружениям
    implementation.md                   где в системе → как реализуем → план → риски → журнал
    comments.md                         комментарии: свои черновики и подтянутые из трекера
    context/…                           вложения, треды, снапшоты, выдержки из API
  {{TASK_PREFIX}}-0003-slug/            эпик (type: epic) — всегда папка; задачи эпика — внутри, по тем же правилам
  LOC-0001-slug.md                      remote-режим: задача без тикета (`local_prefix`, `trk.sh next-id`), не публикуется
parked/  done/YYYY-MM/                  заморожено / закрыто — двигается только верхний уровень (внутри эпика — статус)
proposals/                              находки «стоило бы сделать» — сырьё для /refine, не в задачу и не в код
notes/                                  сырьё: списки багов, идеи, обрывки; notes/private/ — не в git
```
- Единица = файл или папка, имя начинается с id; у папки главный файл называется как папка. Файл ↔ папка:
  `trk.sh promote <ID>`. Принадлежность эпику — по расположению (поля `epic:` нет). Вложенность — один уровень.
- **Id.** Локальный режим — `{{TASK_PREFIX}}-NNNN` из `trk.sh next-id`. Remote — **id задачи = ключ трекера**
  (`task_prefix` = его очередь): тикет создаётся первым (`/tracker-add`) или подтягивается (`/tracker-pull`, `/task`);
  `remote:` повторяет id и означает «привязана».
- **`INDEX.md`** появляется вместе с папкой; в трекер не уезжает (как и `implementation.md`, `comments.md`, `context/`).

## Frontmatter (`TEMPLATE-task.md`)
Обязательны `id`, `type` (`task | epic`), `title`, `status` (`idea | todo | in-progress | needs-decision | parked |
someday | done`), `created` (`trk.sh now`, не по памяти), `closed` (при `done`), `remote`, `remote_synced` (когда
описание опубликовано; пусто = файл впереди трекера). `priority / size / estimation / repos / depends` — в локальном
режиме питают `board`/`ready`; **у привязанных к трекеру задач необязательны** (это живёт в трекере) — заполнять
только у `LOC-*` или когда реально помогает. `estimation` заполняет только `/estimate` по явному запросу.
`depends` принимает и `ADR-NNNN` (`workspace/docs/decisions/`): задача заблокирована, пока решение не `accepted`.
Задача-вопрос (`needs-decision`) закрывается принятым ADR — критерий готовности «ADR-NNNN accepted».

## Файлы задачи
- **Постановка** — язык поведения системы: `## Контекст / Проблема` → `## Что делаем` → `## Не входит` →
  `## Открытые вопросы` (если есть) → `## Критерии готовности` (одна проверяемая строка на пункт — наблюдаемый
  результат). У эпика между «Не входит» и вопросами — `## Состав работ` (список задач по id). Разбор «как и в каких
  файлах», SQL, runbook-и — в `implementation.md`. Ссылки на задачи — голым id; пути к локальным файлам — в `INDEX.md`.
  Постановка — снимок, не журнал: решённый вопрос вписывается в «Что делаем», пункт удаляется; истории решений нет.
  Локальные постановки держать компактными (M ≤ 70 строк, эпик ≤ 80 — иначе дробить); зеркала трекера — какие есть.
- **`implementation.md`** — живой документ работы: «Где в системе» (что/где) → «Как реализуем» → «План» → «Риски» →
  «Журнал» (датированные записи по ходу). Постановку не повторяет.
- **`comments.md`** — история: `# <ID> — комментарии`, `last_remote_comment: <id>`, записи
  `## <trk.sh now> — <автор> (роль) · трекер #<id> | локально`, хронологически, не редактируются. Комментарий,
  меняющий постановку, → правка «Что делаем» + строка «→ Постановка обновлена». Отправленный — «→ Отправлен в
  трекер #<id>». Подтягивание — только новые (`id > last_remote_comment`).

## Публикация в удалённый трекер (режим remote)
В трекер уезжает тело постановки без frontmatter. **Только через нормализатор** — иначе форматирование разъедется:
`trk.sh publish <ID> --diff` (показать diff, только осмысленные правки) → `--json` (payload) → инструмент
редактирования из `tracker.remote_transport` → `remote_synced: <trk.sh now>`. Комментарии — тем же `normalize.py`.
Нормализатор сверяй с тем, как **твой** трекер реально хранит описания (опубликовать → сравнить), и не меняй без
повторной сверки. Локально пиши с переносами (~110 знаков) — `publish` склеит. Если транспорт не умеет сохранять
вложения на диск — сохранять текстовую копию содержимого в `context/attachment-<id>-<slug>.md` и ссылаться на
вложение в трекере.

## Жизненный цикл
1. **Завести**: `TEMPLATE-task.md`, `created` = `trk.sh now`, `status: todo`; в эпик — положить в его папку.
   Remote — тикет первым (`/tracker-add`), id = его ключ.
2. **Взять**: remote — `/task <KEY>` (подтянуть тикет, `status: in-progress`, ветка в сервисе); local — `/next-task`
   (из `ready`: `status: todo`, не `L`, `depends` закрыты, эпик не заблокирован). Негодная задача (неясно, устарела) —
   `needs-decision` + «Открытые вопросы», остановиться.
3. **Работать**: разведка и план в `implementation.md`; находки — `proposals/`; черновики комментариев — `comments.md`.
4. **Сдать** — `/task-done`: проверки, саммари в трекер, `status: done`, `closed` = `trk.sh now`; верхний уровень —
   `git mv` в `done/YYYY-MM/` (внутри эпика — оставить; эпик уезжает целиком, когда закрыт).
5. **Заморозка** — верхний уровень: `status: parked` + `git mv` в `parked/`; внутри эпика — только статус.
6. Коммит в этом репо: `{{TASK_PREFIX}}-0001: <что сделано>` — вместе с работой в сервисах (`git -C <repo> …`).
   **Проверка** — `trk.sh check`.
