# tracker/ — задачи и работа над ними

Все пути — от корня проекта. Скрипты: `workspace/bin/tracker/trk.sh` (`board | ready | check | gate | next-id | now |
promote{{#if tracker=remote}} | publish{{/if}}`). Курируемого INDEX нет — дашборд строится из frontmatter.
{{#if tracker=remote}}
Истина по задачам — удалённый трекер; здесь **зеркало** постановки плюс то, чего в трекере нет: разведка кода, план,
журнал, черновики комментариев, материалы. Подтянуть — `/tracker-pull`; взять, сделать и сдать — `/next-task <KEY>`;
завести — `/tracker-add`; входящие разбирает `/refine`.
{{#else}}
Истина по задачам — здесь, в файлах. Взять, сделать и сдать — `/next-task`; завести — `/tracker-add`; входящие
разбирает `/refine`.
{{/if}}

## Раскладка
```
tasks/                                  живое
  {{TASK_PREFIX}}-0001-slug.md                      задача без контекста — файл
  {{TASK_PREFIX}}-0002-slug/                        задача с контекстом — папка
    {{TASK_PREFIX}}-0002-slug.md                    постановка{{#if tracker=remote}} (зеркало описания в трекере){{/if}}
    implementation.md                   как реализуем → риски → журнал (M/L; создаёт trk.sh promote)
    comments.md                         заметки по ходу{{#if tracker=remote}}, черновики и подтянутые комментарии трекера{{/if}}, хронологически
    context/…                           вложения: снапшоты, замеры, выдержки{{#if tracker=remote}}, треды из трекера{{/if}}
    INDEX.md                            только когда есть вложения или порядок чтения эпика
  {{TASK_PREFIX}}-0003-slug/                        эпик (type: epic) — всегда папка; его задачи — внутри, по тем же правилам
{{#if tracker=remote}}
  {{LOCAL_PREFIX}}-0001-slug.md                     задача без тикета (`local_prefix`, `trk.sh next-id`) — не публикуется
{{/if}}
parked/  done/YYYY-MM/                  заморожено / закрыто и отменено — двигается только верхний уровень
notes/  proposals/  friction/           входящие для /refine — раздел «Входящие»
```
- Единица = файл или папка с именем от id; главный файл папки называется как папка; вложенность — один уровень,
  принадлежность эпику — по расположению (поля `epic:` нет).
{{#if tracker=remote}}
- **Id задачи = ключ трекера** (`task_prefix` = его очередь): тикет создаётся первым (`/tracker-add`) или
  подтягивается (`/tracker-pull`); `remote:` повторяет id и означает «привязана». Задача без тикета —
  `{{LOCAL_PREFIX}}-NNNN` из `trk.sh next-id`.
{{#else}}
- Id — `{{TASK_PREFIX}}-NNNN` из `trk.sh next-id`.
{{/if}}
- Папка нужна задачам M/L, любой с вложениями или деталями реализации, известными при заведении (`trk.sh promote
  <ID>` — создаёт `implementation.md`); задача S живёт файлом — её заметки идут в коммит и в `comments.md` эпика.

## Frontmatter (`TEMPLATE-task.md`)
Обязательны `id`, `type` (`task | epic`), `title`, `status` (таблица «Состояния» ниже), `created` (`trk.sh now`, не по
памяти), `closed` (при `done` и `cancelled`). `priority / size / repos / depends` питают `board`/`ready`: `size` —
грубо (S/M/L), без анализа кода; `depends` — id задач, которые должны быть `done` (отменённая не блокирует, но
`trk.sh check` просит пересмотреть задачу){{#if adr}}, и/или `ADR-NNNN` — задача ждёт, пока решение не `accepted`{{/if}}.
{{#if tracker=remote}}
`remote` — ключ трекера, `remote_synced` — когда описание опубликовано (пусто = файл впереди трекера); у привязанных
задач `priority / size / repos / depends` необязательны — это живёт в трекере.
{{/if}}
{{#if estimates}}
`estimation` заполняет только `/estimate` по явному запросу.
{{/if}}

## Файлы задачи
- **Постановка** — структура и подсказки по разделам — `workspace/tracker/TEMPLATE-task.md`,
  `workspace/tracker/TEMPLATE-epic.md`; правила текста — «Как писать». Сверх шаблона: критерий выполним в самой
  задаче, а не требует результата задачи после неё в `depends` или «Составе работ» (критерий «X удалён» — у задачи,
  переводящей потребителей X); критерий с числом — из замера, не оценка на глаз. Постановка — снимок, не журнал:
  решённый вопрос вписывается в «Что делаем», пункт удаляется. Дробить, когда в задаче несколько независимых
  результатов со своими критериями.
- **`implementation.md`** (M/L; заголовки создаёт `promote`) — «Как реализуем» (решения, которых не видно из кода:
  что где меняем и почему, ссылки на техдоки) → «Риски» → «Журнал» (датированные записи: сделано, грабли, цифры). Не
  повторяет постановку и не пересказывает код{{#if adr}}; сдвиг границы — ссылка на ADR{{/if}}. Следующая задача читает только «Журнал».
- **`comments.md`** — `# <ID> — комментарии`, записи `## <trk.sh now> — <автор>{{#if tracker=remote}} (роль) · трекер #<id> | локально{{/if}}`
  хронологически, не редактируются. Комментарий, меняющий постановку, → правка «Что делаем» + строка «→ Постановка
  обновлена».{{#if tracker=remote}} В шапке `last_remote_comment: <id>`; отправленный — «→ Отправлен в трекер #<id>»; подтягивание — только новые.{{/if}}
- **`INDEX.md`** — что лежит в `context/` и порядок чтения; у эпика — порядок чтения доков перед работой. Без
  вложений и особого порядка не заводится{{#if tracker=remote}}; в трекер не уезжает (как и `implementation.md`, `comments.md`, `context/`){{/if}}.

## Как писать: задача, предложение, трение
- **Самодостаточно.** Агент в новой сессии, не видевший обсуждения, из одного текста понимает, что не так, что
  должно получиться и как проверить.
{{#if tracker=remote}}
- **Постановка — для трекера.** Ни путей к локальным файлам, ни имён из личного слоя; другие задачи — по ключу,
  доки — по названию; что оттуда нужно — фразой. Локальное — `INDEX.md`, `implementation.md`.
{{#else}}
- **Ссылки и числа несут смысл.** Термин вне глоссария — фраза при первом упоминании; ссылка на {{#if adr}}ADR, {{/if}}задачу или док —
  с тем, что оттуда нужно, не голый id; число — с тем, что считается и в каком сценарии.
{{/if}}
- **Механика, а не реализация.** Постановка описывает правила поведения, термины и контракты; имена из кода — когда
  это контракт или адрес. Структуры, алгоритмы, файлы под правку, порядок шагов, отвергнутые варианты, риски —
  `implementation.md` (всплыли при заведении — `trk.sh promote`). Фраза, которая изменится при другой реализации с
  тем же наблюдаемым результатом, — реализация.
- **Понятный язык.** Полные предложения, одна мысль — одно предложение, перечисление — списком, словечки сессии
  раскрыты или заменены стандартными терминами.
- **Без лишнего.** История обсуждения — `comments.md`, пересказ кода и доков — ссылка и фраза, ход работы — «Журнал».

## Входящие: `notes/`, `proposals/`, `friction/`
Разбирает `/refine`: обработанный файл удаляется (заметка — помечается). В контекст исполнения задачи не входят.
- **`notes/`** — сырьё человека: списки багов, идеи, обрывки, любой формат. `notes/private/` — не в git.
- **`proposals/`** — находки агента «стоило бы сделать», не в задачу и не в код: файл на проблему
  `YYYY-MM-DD-slug.md` по `workspace/tracker/TEMPLATE-proposal.md`, самодостаточный.
- **`friction/`** — инструкция, док или скрипт, который помешал: послал не туда или допускал два прочтения; прочитан
  впустую; неописанные грабли съели ≥ 2 попытки; скрипт упал не по вине задачи. Файл на случай `YYYY-MM-DD-slug.md`
  по `workspace/tracker/TEMPLATE-friction.md` тогда, когда заметил; повтор — дата и задача в «Случаи» существующего
  (число случаев — приоритет); исправлено в той же задаче — только поле «трение» в отчёте. Нечего назвать файлом —
  это не трение. Адрес правки: грабли кода → `<repo>/CLAUDE.local.md`; маршрутизация и правила → `AGENTS.md` корня
  или `workspace/prompts/`; нехватка знаний → `workspace/docs/` по матрице; скрипт → `workspace/bin/`.
{{#if tracker=remote}}

## Публикация в удалённый трекер
В трекер уезжает тело постановки без frontmatter. **Только через нормализатор** — иначе форматирование разъедется:
`trk.sh publish <ID> --diff` (показать diff, только осмысленные правки) → `--json` (payload) → инструмент
редактирования из `tracker.remote_transport` → `remote_synced: <trk.sh now>`. Комментарии — тем же `normalize.py`.
Нормализатор сверяй с тем, как **твой** трекер реально хранит описания (опубликовать → сравнить), и не меняй без
повторной сверки. Локально пиши с переносами (~110 знаков) — `publish` склеит.
{{/if}}

## Состояния и переходы
Файл двигается только на верхнем уровне (`git mv`); внутри эпика меняется только статус.

| Статус | Где лежит | Кто переводит | Что ещё |
|---|---|---|---|
| `idea`, `todo` | `tasks/` | `/tracker-add` заводит `todo`{{#if tracker=remote}}, `/tracker-pull` — по статусу трекера{{/if}} | в эпик — в его папку и строкой в «Состав работ» |
| `in-progress` | `tasks/` | `/next-task` при взятии из `ready` (`todo`, не `L`, `depends` закрыты, эпик не заблокирован) | `priority: now` |
| `needs-decision` | `tasks/` | `/next-task`: неясно, устарела, нужно решение человека | вопросы — в «Открытые вопросы»{{#if adr}}; закрывается принятым ADR — критерий «ADR-NNNN accepted», черновик — `/adr`{{/if}} |
| `parked`, `someday` | `parked/` | человек | причина и условие возврата — пункт в «Открытые вопросы» |
| `done` | `done/YYYY-MM/` | `/next-task` при сдаче; `closed` = `trk.sh now` | **эпик:** закрыта последняя задача состава (отменённая считается закрытой) и критерии отмечены — эпик закрывается тем же ходом без подтверждения: статус, `closed`, папка целиком в `done/`{{#if team=solo}}, этап в `workspace/docs/ROADMAP.md` закрыт с датой{{/if}}; критерий не отмечен — эпик остаётся `in-progress`, сказать какой{{#if tracker=remote}}; статус тикета — по подтверждению{{/if}} |
| `cancelled` | `done/YYYY-MM/` | решил человек{{#if adr}}; принятый ADR убрал предмет{{/if}}; поглотила другая задача | `closed`; в конце постановки `## Итог` — почему и куда делся предмет; у отменённого эпика открытые задачи тоже `cancelled`; задачи с ней в `depends` — пересмотреть (`trk.sh check`) |

Коммит: `{{TASK_PREFIX}}-0001: <что сделано>` (правила — `AGENTS.md` корня). Проверка — `trk.sh check`.
