# tracker/ — правила трекера

Все пути — от корня проекта. Скрипты: `workspace/bin/tracker/trk.sh` (`board | ready | check | gate | next-id | now |
publish | promote`). Курируемого INDEX нет — дашборд строится из frontmatter.

## Единица работы = файл или папка; эпик = папка
```
tasks/                                  всё живое
  {{TASK_PREFIX}}-0001-slug.md          задача без контекста — файл
  {{TASK_PREFIX}}-0002-slug/            задача с контекстом — папка
    {{TASK_PREFIX}}-0002-slug.md        сама задача — файл с именем папки (постановка)
    INDEX.md                            точка входа в папку: что здесь лежит и в каком порядке читать
    implementation.md                   реализация: где в системе, как делаем, план, риски, журнал
    comments.md                         комментарии — свои и из удалённого трекера
    context/…                           материалы: треды, выдержки из API, снапшоты, вложения из трекера
  {{TASK_PREFIX}}-0003-slug/            эпик (type: epic) — всегда папка
    {{TASK_PREFIX}}-0003-slug.md        сам эпик — файл с именем папки
    INDEX.md, context/…                 по тем же правилам
    {{TASK_PREFIX}}-0004-slug.md        задачи эпика — файлы или папки по тем же правилам
  LOC-0001-slug.md                      remote-режим: задача без тикета в трекере (local_prefix)
parked/                                 заморожено — только верхний уровень (файл/папка целиком)
done/YYYY-MM/                           закрыто — только верхний уровень, месяц закрытия
proposals/                              находки в ходе работы «стоило бы сделать» — сырьё для /refine
notes/                                  сырьё: списки багов, идеи, обрывки; notes/private/ — не в git
```
- Единица — файл или папка, чьё имя начинается с id; у папки главный файл называется как папка.
  Эпик отличается от задачи только `type: epic` и тем, что содержит единицы внутри. Всё, что не начинается с
  префикса id (`INDEX.md`, `implementation.md`, `comments.md`, `context/`), — контекст единицы.
- **Id.** Локальный режим: `{{TASK_PREFIX}}-NNNN` из `trk.sh next-id`. **Remote-режим: id задачи = ключ удалённого
  трекера** (`task_prefix` = его очередь), ничего не придумываем — тикет создаётся первым, файл получает его ключ;
  `remote:` повторяет id и означает «привязана». Задачи, которым тикет не нужен, — `local_prefix` (`LOC-0001`,
  `trk.sh next-id`), в трекер они не публикуются и в постановках привязанных задач не упоминаются.
- **`INDEX.md` — точка входа в папку**: что лежит и зачем, порядок чтения, состояние окружений, ссылки на доки.
  Появилась папка — появился `INDEX.md`. В трекер не публикуется.
- **Принадлежность эпику — по расположению**, поля `epic:` нет.
- **«Температура» (tasks/parked/done) — только на верхнем уровне.** Внутри эпика ничего не двигается: закрытая
  задача остаётся на месте со `status: done` + `closed:`; эпик уезжает в `done/` целиком, когда его закрыли.
- Вложенность — один уровень: эпик содержит задачи, задача задач не содержит (нужна группировка → второй эпик).
- Файл ↔ папка обратимо: `trk.sh promote <ID>` переносит файл единицы в одноимённую папку.

## Frontmatter задачи (`TEMPLATE-task.md`)
```yaml
id: {{TASK_PREFIX}}-0001        # единственный устойчивый идентификатор; имя файла/папки начинается с него
type: task                      # task | epic
title: …
status: todo                    # idea | todo | in-progress | needs-decision | parked | someday | done
priority: normal                # now | soon | normal | later — осмыслен только для берущейся работы
size: M                         # S | M | L (L — дробить); грубая оценка при заведении, без анализа кода
estimation: ""                  # SP/часы — заполняет только /estimate по явному запросу; при заведении не оценивать
repos: [backend, frontend]      # из project.yaml
depends: []                     # id задач-блокеров
remote: ""                      # remote-режим: = id, если задача есть в трекере; пусто — локальная
remote_synced: ""               # когда описание опубликовано; пусто = файл впереди трекера
created: 2026-08-28 14:05       # дата и время — из `trk.sh now`, не по памяти
closed: ""
```
Эпик (`TEMPLATE-epic.md`): `type: epic`, без `priority/size/estimation/depends`.

## Главный файл и `implementation.md`
Главный файл — **постановка**: что и зачем делаем, как должно работать, когда готово. Формат один для задач и
эпиков, для локального и удалённого режима:
`## Контекст / Проблема` → `## Что делаем` → `## Не входит` → `## Открытые вопросы` (если есть) →
`## Критерии готовности`. У эпика между «Не входит» и вопросами — `## Состав работ` (список задач по id).
Дополнительные разделы допустимы, если без них не обойтись (например, «Как воспроизвести» у бага), но общий
порядок и смысл разделов сохраняются.
- **Язык постановки.** Пишем о поведении системы и продукта. Технические детали — те, что нужны для понимания
  (сущность, событие, где хранится, ограничение, замер), допустимы. Разбор «как и в каких файлах это сделать»,
  SQL, команды и runbook-и — не сюда, а в `implementation.md`. Задачи — голым id, сценарии — UC-id; ссылок на
  локальные файлы и скрипты в постановке нет (они — в `INDEX.md`).
- **`implementation.md`** — рядом (задача становится папкой: `trk.sh promote`), когда реализацию есть что
  описывать: «Где в системе» (таблица что/где) → «Как реализуем» → «План» → «Риски» → «Журнал». Живой документ:
  заполняется при разборе кода, дополняется по ходу работы. Постановку не повторяет.
- **Файл — снимок, не журнал.** В постановке нет заметок по ходу работы, датированных слоёв и истории решений —
  история в git и в коммитах. Рабочие записи, если нужны, — в `implementation.md → Журнал`.
- **Вопросы — в самой постановке**, раздел «Открытые вопросы»: продуктовые и технические, каждый — вопрос,
  варианты (таблица «как работает / плюс / минус» при 2+ вариантах), рекомендация, адресат. Блокирует старт →
  `status: needs-decision`. **Решён — «Что делаем» переписывается так, будто вопроса не было, пункт удаляется.**
  Отдельного реестра решений нет: действующее правило всегда в «Что делаем».
- **Критерий готовности — одна проверяемая строка**: наблюдаемый результат, без «заодно», без дописывания
  результата выполнения в пункт.
- Размер: S ≈ 20–30 строк, M ≤ 70, эпик ≤ 80. Больше — реализация лезет в постановку или пора дробить.
- **Локально пишем с переносами** (~110 знаков), так читается. Для трекера переносы склеивает `publish`.

## Комментарии — `comments.md`
Постановка — снимок, комментарии — история; они живут в `comments.md` папки задачи (файл → папка через
`trk.sh promote`), одинаково для локальных и подтянутых из трекера. В трекер файл не уезжает.
```markdown
# {{TASK_PREFIX}}-0002 — комментарии
last_remote_comment: 4471            # id последнего подтянутого комментария трекера (пусто — локальный режим)

## 2026-08-28 14:05 — Иван (QA) · трекер #4471
На stage у 12 объектов рейтинг 0 при трёх отзывах. Скрин — context/qa-2026-08-28.png.

## 2026-08-28 16:20 — Алекс · локально
Это отзывы, скрытые модерацией: они не должны входить в расчёт. → Постановка обновлена («Что делаем», п. 1).
→ Отправлен в трекер #4480.
```
- Заголовок записи: время (`trk.sh now`) — автор (роль) — источник: `трекер #<id>` или `локально`. Автор локальной
  записи — `git config user.name`. Порядок — хронологический, записи не редактируются.
- Комментарий — повод, а не хранилище решения: если он меняет постановку, правится «Что делаем» / «Открытые
  вопросы», а в записи одной строкой — «→ Постановка обновлена».
- Ответ в трекер: запись `локально`, публикация через `/tracker-comment`, приписка «→ Отправлен в трекер #<id>».
- Подтягивание из трекера — `/tracker-pull <KEY>`: только записи с id > `last_remote_comment`, без дублей.
- Двое работают локально — один файл, обычный git; конфликт решается как в коде.

## Режим `remote` (`project.yaml: tracker`)
В трекер уезжает **всё тело главного файла**; frontmatter отбрасывается. `trk.sh publish <ID>` печатает текст
для трекера: переносы внутри абзаца склеены, ссылки на локальные файлы превращены в текст, упоминания задач
`local_prefix` подсвечены (с предупреждением — лучше ни того ни другого в постановке не иметь). Id задач и есть
ключи трекера, поэтому ссылки по id работают в трекере как есть. Перед публикацией —
`trk.sh publish <ID> --diff`, показать diff; после — `remote_synced: <trk.sh now>`. `--json` — готовый payload
для инструмента редактирования задачи. `INDEX.md`, `implementation.md`, `comments.md`, `context/` в трекер не уезжают.
Обратное направление — `/tracker-pull <KEY>`: описание, вложения (`context/`) и комментарии (`comments.md`).

## Жизненный цикл
1. **Завести**: `TEMPLATE-task.md`, `created` = `trk.sh now`, `status: todo`; в эпик — положить в его папку.
   Id: локальная задача — `trk.sh next-id`; задача трекера — ключ созданного тикета (`/tracker-add`) или
   существующего (`/tracker-pull`). `estimation` не заполнять.
2. **Взять**: `status: in-progress`, `priority: now`; коммитить вместе с работой (`git -C` в каждом репо + этот репо).
3. **Закрыть**: `status: done`, `closed` = `trk.sh now`; верхний уровень — `git mv` в `done/YYYY-MM/`; внутри эпика — оставить.
   Отбраковал готовую — сразу `needs-decision` с пунктом в «Открытые вопросы».
4. **Закрыть эпик**: все задачи в терминальном статусе (или принято решение закрыть) → `status: done`, `closed:`,
   `git mv tasks/<эпик> done/YYYY-MM/`.
5. **Находки** — файл в `proposals/`, не расширять задачу. **Блокеры** — `depends:`.
6. **Заморозка** — верхний уровень: `status: parked` + `git mv` в `parked/`; внутри эпика — только статус.
7. Коммит в этом репо: `{{TASK_PREFIX}}-0001: <что сделано>`; в репо сервисов — по их правилам со скоупом задачи.
   Проверять `git show --stat`: `git add` с битым pathspec прерывает всю операцию.

## `ready` (что можно брать)
`status: todo`, не `L`, все `depends` закрыты, и — для задач эпика — эпик не в `needs-decision|parked|someday|done`.

## Что читать перед взятием задачи
Задача: если папка — сначала `INDEX.md`, по нему постановка → `comments.md` → `implementation.md` → `context/` по
ссылкам. Затем
эпик тем же порядком (`INDEX.md` → файл эпика), `AGENTS.md` затронутых сервисов, нужные `workspace/docs/`.
`notes/` и `proposals/` в контекст исполнения не входят.
