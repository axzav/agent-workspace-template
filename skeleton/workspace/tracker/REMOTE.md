# tracker/ — удалённый трекер (профиль `tracker: remote`)

Дополняет `workspace/tracker/AGENTS.md` и главнее его там, где расходится. Истина по задачам — трекер; здесь
**зеркало** постановки плюс то, чего в трекере нет: разведка кода, план, журнал, черновики комментариев, материалы.
Подтянуть — `/tracker-pull <KEY>` (`/next-task <KEY>` подтягивает сам); комментарий — `/tracker-comment <ID> <текст>`;
описание в трекер — `/task-description <ID>`. Скрипт — `trk.sh publish <ID> [--diff | --json]` (обёртка над
`workspace/bin/tracker/normalize.py`). Транспорт — `project.yaml: tracker.remote_transport`.

## Id и frontmatter
- **Id задачи = ключ трекера** (`task_prefix` = его очередь): тикет создаётся первым (`/tracker-add`) или
  подтягивается (`/tracker-pull`); `remote:` повторяет id и означает «привязана». Задача без тикета —
  `{{LOCAL_PREFIX}}-NNNN` из `trk.sh next-id` (`project.yaml: local_prefix`), лежит в `tasks/` как
  `{{LOCAL_PREFIX}}-0001-slug.md` и не публикуется.
- `remote_synced` — когда описание опубликовано (пусто = файл впереди трекера, `trk.sh check` предупреждает); у
  привязанных задач `priority / size / repos / depends` необязательны — это живёт в трекере.
- `/tracker-pull` заводит задачу со статусом трекера. Статус тикета при закрытии задачи или эпика — по подтверждению
  человека, файл двигается по таблице состояний.

## Что уезжает в трекер, что нет
- **Постановка — для трекера.** Ни путей к локальным файлам, ни имён из личного слоя; другие задачи — по ключу, доки —
  по названию; что оттуда нужно — фразой. Локальное (`implementation.md`, `comments.md`, `context/`) — только в
  `INDEX.md`, в трекер не уезжает.
- `context/` держит и треды из трекера; транспорт не сохраняет файлы — вложение копируется текстом как
  `context/attachment-<id>-<slug>.md`.

## Комментарии
Запись в `comments.md`: `## <trk.sh now> — <автор> (роль) · трекер #<id> | локально`. В шапке файла
`last_remote_comment: <id>` — подтягиваются только новые. Отправленный из локальной записи — строка
«→ Отправлен в трекер #<id>».

## Публикация
В трекер уезжает тело постановки без frontmatter. **Только через нормализатор** — иначе форматирование разъедется:
`trk.sh publish <ID> --diff` (показать diff, только осмысленные правки) → `--json` (payload) → инструмент
редактирования из `tracker.remote_transport` → `remote_synced: <trk.sh now>`. Комментарии — тем же `normalize.py`.
Нормализатор сверяй с тем, как **твой** трекер реально хранит описания (опубликовать → сравнить), и не меняй без
повторной сверки. Локально пиши с переносами (~110 знаков) — `publish` склеит.
