# discussions/ — обсуждения переработки

Обсуждение переработки системы, которое не укладывается в одну сессию и в один ADR: несколько подтем, несколько
решений, между ними связи и противоречия. Это **рабочие документы**, а не сырьё и не источник истины: истина по
поведению — код, по принятому — доки уровня 2 и ADR. Из обсуждения вырастают ADR (`workspace/docs/decisions/`),
правки уровня 2 и задачи трекера; само оно после этого удаляется.

Чем отличается от соседей: `workspace/docs/raw/` — дословные треды, не правятся; `workspace/tracker/proposals/` —
одна находка → одна задача; ADR — один зафиксированный выбор; эпик трекера — исполнение уже решённого.

## Раскладка
Одно обсуждение — одна папка `<тема>/` (kebab-case, без даты: дата и статус — в индексе ниже). Внутри:
- `README.md` — зачем, карта подтем со статусами, «решено и не переоткрывается» (короткий список в языке поведения),
  что уже сделано по итогам обсуждения. Правила ведения не повторять — они здесь.
- По файлу на подтему по `workspace/docs/discussions/TEMPLATE-topic.md`: **Как сейчас** (что делает код на дату
  сверки) → **Решено** (что выбрал человек, с датой) → **Открыто** (вопросы с вариантами, у каждого плюсы и минусы) →
  **Связи** (какие подтемы задевает). Файлы нумеруются в порядке чтения: `01-slug.md`.
- Замеры, таблицы, выдержки — прямо в файле подтемы или в README обсуждения; отдельных вложений нет.

## Как вести
- «Решено» пишется в языке поведения системы, без имён функций и файлов кода. Числа — с указанием, где они лежат.
- Спорное не переписывается молча: старый вариант остаётся в «Открыто», пока человек не выбрал.
- **Открытые вопросы идущего обсуждения живут в нём.** В концепции — одна строка со ссылкой на обсуждение, не копия.
- Пока подтема не закрыта ADR, доки уровня 2 описывают прежнюю модель и правятся в момент принятия ADR; задачи по
  подтеме не заводятся (кроме дефектов и замеров).
- Подтема закрыта: ADR принят, уровень 2 обновлён — в шапке файла «Закрыто ADR-NNNN», в карте подтем статус
  «закрыто».
- Обсуждение закрыто (все подтемы закрыты, задачи заведены): папка удаляется, строка индекса получает итог
  (ADR, эпик). Отвергнутые варианты к этому моменту обязаны быть в ADR («Варианты обязательны»), текст — в git.
  Так `docs/` остаётся описанием текущего состояния, а не журналом.
- Пути в бэктиках — от корня проекта целиком: папку проверяет `workspace/bin/check/links.sh`.
- Термины стандартные (`AGENTS.md` корня): слово, всплывшее в обсуждении, в доки и код не разносится.
- Обсуждение, тема которого — сам слой агента (инструкции, доки, скрипты), ведётся здесь же по тем же правилам:
  README с картой шагов и статусами, итог — правки инструкций и принципы.
