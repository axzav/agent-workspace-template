## Как работать
Смотреть на тип запроса, а не на один сценарий:
- **Изменение кода или поведения** — только через трекер: `/next-task` (взять задачу, сделать, сдать; начатую —
  продолжить). Правила трекера — `workspace/tracker/AGENTS.md`; перед кодом — `<repo>/AGENTS.md`, затем его карта
  техдоков (файл темы по одному, не всё подряд).
- **Ресёрч, обсуждение, правка знаний** — задачу не заводить: читать и править `workspace/docs/` по индексу
  `workspace/docs/README.md` (матрица «что изменилось → куда писать»).
{{#if adr}}
  Принятое (ADR) не переспрашивать; открытые вопросы — там же. **Переработка системы в несколько сессий** — обсуждение
  `workspace/docs/discussions/…/` (правила — README папки): решённое уезжает в ADR и доки, задачи — после ADR.
{{/if}}
- **Новая задача** — `/tracker-add`; **заметки, предложения, трение и разбор находок** — `/refine [текст]`;
  **проверки слоя** — `workspace/bin/check/all.sh` (их же гоняет хук pre-commit).
{{#if adr}}
- **Архитектурное решение** — `/adr` (черновик `proposed`; кто и когда принимает — `workspace/docs/decisions/README.md`).
{{/if}}
{{#if tracker=remote}}
- **Удалённый трекер** — подтянуть тикет `/tracker-pull <KEY>`, комментарий `/tracker-comment <ID> <текст>`, описание
  в трекер `/task-description <ID>`; `/next-task <KEY>` подтягивает сам.
{{/if}}
{{#if team=team}}
- **Замечания к MR** — `/fix-mr`.
{{/if}}
{{#if estimates}}
- **Оценка задачи** — `/estimate <ID>` (только по явной просьбе).
{{/if}}
Читать по потребности запроса, а не всё сразу.

## Правила
- **Архитектуру, границы и ключевые абстракции решает человек.** Агент предлагает варианты и пишет код внутри
  принятых границ; спорное — в `workspace/tracker/proposals/` или вопросом, не молчаливым решением в коде.
{{#if adr}}
- **Архитектурное решение = ADR** в `workspace/docs/decisions/` (`/adr`). Задача с `depends: [ADR-NNNN]` ждёт принятия;
  изменилась граница — нужен принятый ADR, иначе задача не сдаётся. Принятые решения не переоткрывать без явной
  просьбы; открытые вопросы — сначала решение, потом код.
{{#else}}
- Решения о стеке, границах и контрактах принимает команда там, где она их принимает; здесь — только ссылка на итог
  и правило для агента, если оно из этого следует.
{{/if}}
{{#if team=team}}
- **Инструкции и доки команды** (`<repo>/AGENTS.md`, `CLAUDE.md`, `docs/`) **не редактировать** без задачи на это;
  мои переопределения и грабли — `<repo>/CLAUDE.local.md` (не в git репо). Ни один файл в репо не ссылается на этот
  слой (`workspace/`, корень) — у команды его нет.
{{/if}}
{{#if tracker=remote}}
- **Тело задачи уезжает в трекер:** в постановке и комментариях — ни путей к локальным файлам, ни имён из этого слоя;
  другие задачи — по ключу, доки — по названию. Локальное (`implementation.md`, `context/`) — только в `INDEX.md`.
{{/if}}
- **Термины — стандартные.** Этап (не «веха»), задача, решение, проверка. Необычное слово из обсуждения не разносить
  по докам и коду; новый термин предметной области — через глоссарий в `workspace/docs/`.
- **Трение называть, а не молчать:** инструкция, док или скрипт помешал — файл в `workspace/tracker/friction/` тогда,
  когда заметил, и поле «трение» в отчёте задачи (порог и формат — `workspace/tracker/AGENTS.md`, «Входящие»).
  Нечего назвать файлом — «трение: нет».
- **Рабочий каталог оболочки плывёт между вызовами:** `cd` — только в подоболочке `(cd <repo> && …)`, любой `git`,
  скрипт и путь — через `git -C` или абсолютный путь.
- **Пути в бэктиках — от корня проекта целиком** (`workspace/docs/README.md`, `<repo>/docs/…`); markdown-ссылка
  `[…](…)` — от корня или от папки файла. Проверяет `workspace/bin/check/links.sh`. Переименовал или перенёс файл —
  `grep` старого пути по `workspace/` и репо до коммита.
{{#if commit=auto}}
- **Коммит по завершении задачи — сразу, без вопроса**, в каждом репо явно (`git -C <repo> …`); статус задачи, код и
  доки — в одном изменении. Промежуточные коммиты и коммиты вне задачи — спросить. `git push` — только по явной
  просьбе; подагентам передавать запрет push. Коммит не делается агентом — всё равно закончить ответ готовым
  сообщением коммита.
{{#else}}
- **Перед коммитом — спросить**, показав план по репо (`git -C <repo> …`, формат — по правилам репо); статус задачи,
  код и доки — в одном изменении. `git push` и MR — только по явной просьбе; подагентам передавать запрет push.
{{/if}}
{{#if kind=services}}
- Инфраструктурные правки (compose, nginx, `.env`) — в репо инфры, не в сервисах. Ничего на удалённых окружениях
  (stage/prod) без явной просьбы.
{{/if}}
- Секреты — только через переменные окружения (`.mcp.json` использует `${VAR}`); в файлы и чаты не вставлять.
- `project.yaml` — данные для скриптов `workspace/bin`; агент читает его только через скрипты.
- Знания — в `workspace/docs/`; истина по поведению — код. Память агента (`workspace/memory/`) — только датированные
  снимки и факты о коде, которых нет в доках; воспроизводимые правила — сюда или в `<repo>/CLAUDE.local.md`.

| `{{REPO}}/` | репозиторий кода, свой git (база `main`, коммиты `{{TASK_PREFIX}}-NNNN: …`); инструкции — `{{REPO}}/AGENTS.md`, техдоки — `{{REPO}}/docs/README.md`, мои грабли — `{{REPO}}/CLAUDE.local.md` | код |

| `workspace/docs/` | знания по уровням: «что и почему», «как устроено», «обоснования и журналы»; индекс и матрица — `workspace/docs/README.md` | вневременное: «как есть сейчас», не лог |
| `workspace/tracker/` | задачи и эпики, входящие (`notes/`, `proposals/`, `friction/`); правила — `workspace/tracker/AGENTS.md` | временное: берётся, делается, уезжает в `done/` |
| `workspace/prompts/` | тела промптов для `.claude/commands/*` | инструментарий |
| `workspace/bin/` | скрипты (`workspace/bin/README.md`): трекер `trk.sh`, проверки слоя `all.sh`, команды качества `cmd.sh <команда> [repo]`, статус репо `status.sh`; звать абсолютным путём | инструментарий |
| `workspace/memory/` | память агента | только факты о коде и датированные снимки |
| `.claude/` | команды-шимы, настройки; личный слой и хуки — `.claude/README.md` | инструментарий |
| `agent-workspace-template/`, `local/` | клон шаблона слоя; личные скрипты, заметки, дампы | не в git |

Поисковые инструменты уважают `.gitignore`; папки репо возвращает в поиск корневой `.ignore` — не удалять; новый репо —
строка `!/<путь>/` (проверка — `workspace/bin/check/searchignore.sh`).
