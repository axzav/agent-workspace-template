# agent-workspace-template — шаблон корня проекта для работы с AI-агентами

Единый формат для проектов, над которыми работа ведётся из общего корня: один репозиторий кода (monorepo, приложение)
или несколько репо сервисов; один человек или команда; локальный трекер или удалённый. Шаблон самодостаточен: этот репо
клонируется в корень проекта один раз, слой разворачивается `init.sh` по **профилю** и дозаполняется агентом (`/seed`).

## Ключевые идеи
1. **Корень проекта — git-репо слоя агента** (папка называется как угодно). `.gitignore` — белый список: репо с
   кодом, склонированные внутрь, автоматически вне git. Никаких симлинков и генерации после инициализации.
2. **Точка входа** — тонкий `AGENTS.md` (≤ ~100 строк: продукт и стек, маршрутизация по типу запроса, правила,
   карта) + `CLAUDE.md` = `@AGENTS.md`. Так же в каждом репо с кодом. Состояние (текущий этап, «сейчас») в
   инструкциях не живёт — только в `ROADMAP.md`/трекере.
3. **Слой агента — личный целиком** (локальный git, команде не показывается): правила живут прямо в `AGENTS.md`.
   Личное относительно **команды** — `<repo>/CLAUDE.local.md` (единственный файл в репо, который знает о слое;
   заготовка — `repo-template/CLAUDE.local.md.example`), `.claude/settings.local.json`, `local/` — вне git.
4. **Знания (`workspace/docs`) отдельно от работы (`workspace/tracker`)**, истина по поведению — код. Три уровня
   доков («что и почему» / «как устроено» / «обоснования и журналы»), матрица «что изменилось → куда писать».
   Архитектурные решения — ADR (профиль `adr`): агент готовит `proposed`, принимает человек (или агент при явном
   выборе человека), задачи ждут решения через `depends: [ADR-NNNN]`; переработки в несколько сессий — `discussions/`.
5. **Трекер — файлы с frontmatter**, папки по «температуре», эпик — папка с задачами внутри, дашборд из скрипта;
   таблица «состояние → где лежит → кто переводит» в правилах, шаги — в промпте `/next-task` (взять, сделать, сдать).
   Входящие — `notes/` (человек), `proposals/` (находки агента), `friction/` (что мешало в инструкциях) → `/refine`.
6. **Копия правила = ссылка + крючок**: у каждого правила один файл-владелец; таблицы фактов о коде — в техдоках репо,
   инструкция ссылается. Бюджет контекста на типовую команду измеряется (сумма байт файлов, которые грузятся).
7. **Профили вместо мёртвого кода**: remote-трекер, ADR, оценки, healthcheck, toolkit ставятся `init.sh` по ответам,
   а не лежат «на всякий случай». Пути от корня проекта в слое агента; внутри репо — от корня репо; проверяет
   `links.sh`, хук pre-commit гоняет все проверки слоя.
8. `project.yaml` — данные для скриптов `workspace/bin` и профиль: репо с **командами качества**
   (`commands: test/lint/…` — скрипты не угадывают их по Makefile). Агент читает его только через скрипты; значения
   подставлены в инструкции при инициализации.

## Профиль проекта (`init.sh` → `project.yaml: profile`)
| Ключ | Значения | Что меняет |
|---|---|---|
| `kind` | `services` \| `monorepo` \| `app` | таблица репо в манифесте и карте; `contracts/`, `dev/`, `healthcheck.sh`, `/healthcheck` и правило «инфра — в репо инфры» — только для `services` |
| `team` | `solo` \| `team` | `solo`: `ROADMAP.md` со снимком «что делать сейчас», эпик закрывает этап; `team`: доки и инструкции команды не редактировать, в репо нет ссылок на слой, `/fix-mr`; умолчания для `tracker`/`commit`/`adr` |
| `tracker` | `local` \| `remote` | `remote`: `/tracker-pull`, `/tracker-comment`, `/task-description`, `trk.sh publish` + `normalize.py`, поля `remote`/`remote_synced`, `local_prefix`, правило «в постановке ни путей, ни имён из слоя» |
| `commit` | `auto` \| `ask` | коммит по завершении задачи сразу — или спросить и ждать ревью (корень, `/next-task`, `repo-template`) |
| `adr` | `yes` \| `no` | `decisions/` + `adr.sh` + `/adr`, `discussions/`, `depends: [ADR-NNNN]`, шаг «граница → ADR» в `/next-task` |
| `estimates` | `yes` \| `no` | `/estimate`, поле `estimation`, `notes/estimate-history.md` |
| `toolkit` | `yes` \| `no` | `toolkit-sync.sh` и `toolkit.sources` в манифесте |

Что ставится при каком профиле — `init/profiles.txt`; текст с ветвлением — директивы `{{#if …}}` в файлах скелета
(`init/render.py`). Поменять профиль позже — править `project.yaml: profile` и запустить `init.sh` ещё раз: он
доложит недостающие файлы (существующие не трогает; ставшие лишними — удалить руками, скрипт их перечислит как
«не по профилю» при следующем запуске с другим ответом).

## Состав
```
init.sh             фаза 1: развернуть skeleton/ в корень по профилю (флаги или вопросы; повторный запуск — доложить);
                    init.sh render <файл> — отрендерить файл repo-template/ по профилю проекта
init/               render.py (подстановки и {{#if}}), profiles.txt (файл → условие)
sync.sh             развёрнутый слой ↔ шаблон: status/diff — расхождения по профилю, pull — изменения шаблона в проект,
                    push — правки проекта в skeleton/ (трёхстороннее слияние от маркера project.yaml: template), mark
SEED.md             фаза 2: промпт агенту — заполнить карту, манифест, правила, AGENTS.md репо по example/;
                    путь A (репо есть) и путь B (greenfield: только концепт-доки)
SEED-DOCS.md        отдельная команда: наполнить базу знаний по коду (по областям)
PRINCIPLES.md       принципы устройства инструкций и доков, по которым собран шаблон (из рефактора живого проекта)
skeleton/           сам шаблон (плейсхолдеры {{PROJECT}}, {{TASK_PREFIX}}, {{REPO}}, {{…}} для SEED; _claude → .claude,
                    _gitignore → .gitignore при рендере)
example/            заполненный пример — проект Bookly (kind: services, team, remote-трекер): эталон для SEED
repo-template/      заготовки для репо кода: AGENTS.md, CLAUDE.md, CLAUDE.local.md.example, gitignore.snippet,
                    docs/README.md (карта «код → техдок»), scripts/check-docs.sh (гейт ссылок и свежести техдоков)
MIGRATION.md        как перевести существующий проект
.claude/skills/seed скилл /seed (обёртка над SEED.md / SEED-DOCS.md)
```

## Новый или существующий проект
```bash
mkdir myshop && cd myshop                       # или существующий корень
git clone … backend; git clone … frontend       # или ничего, если кода ещё нет
git clone <url> agent-workspace-template        # клон шаблона лежит в корне и остаётся там (для /seed и обновлений)
agent-workspace-template/init.sh .              # фаза 1: вопросы профиля → скелет; или флагами:
#   agent-workspace-template/init.sh . --name myshop --prefix MYS --kind services --team team --tracker remote --commit ask
claude                                          # из корня
> /seed          # или: «прочитай agent-workspace-template/SEED.md и выполни»
> /seed docs бронирования                       # позже, по областям — база знаний
workspace/bin/agent/setup-local.sh && workspace/bin/check/all.sh
git add -A && git commit -m "workspace: init"
```
Агент из корня видит и репо, и шаблон с примером — никаких `--add-dir` и абсолютных путей. Шаблон можно править
прямо в проекте и пушить в общий репо для других проектов. Описание корня для людей — в `AGENTS.md`
(отдельный `README.md` скелет не создаёт).

## Обновление слоя и возврат правок в шаблон
Клон шаблона лежит в корне проекта; точка последней сходимости — `project.yaml: template` (`commit` шаблона,
`project_commit` корня; пишет `init.sh` и `sync.sh mark`). `sync.sh status` — что расходится (проектные файлы вроде
`AGENTS.md`, манифеста и карт доков не сверяются; свои добавить в `template.skip`); `sync.sh pull` — дельта шаблона с
маркера сливается в файлы проекта, специализация (имя репо, термины продукта) сохраняется; `sync.sh push` — правки
проекта с маркера сливаются в `skeleton/`, дальше обобщить руками (`{{REPO}}`, общие термины, `{{#if}}` по профилю) и
закоммитить шаблон. Конфликты — маркеры `<<<<<<<` в файле, код 1, маркер не двигается. В Claude Code всё это делает
`/template-sync`: гоняет скрипт, разбирает конфликты, обобщает формулировки, обновляет `PRINCIPLES.md`.

## Ежедневно
`/next-task [ID|KEY]` (взять или продолжить, сделать, сдать), `/tracker-add`, `/refine [текст]`; по профилю — `/adr`,
`/tracker-pull`, `/tracker-comment`, `/task-description`, `/fix-mr`, `/estimate`, `/healthcheck`; `/template-sync` — сверка
с шаблоном (раздел выше) — шимы в
`.claude/commands`, тела в `workspace/prompts`. Скрипты — `workspace/bin/README.md`: `git/status.sh` — состояние всех
репо, `stack/cmd.sh <команда> [repo]` — команды качества из манифеста, `check/all.sh` — проверки слоя (и хук pre-commit).
