## Контекст / Проблема
При отмене брони сумму возврата считает поддержка вручную; чтобы запустить автоматические возвраты (BOOK-400),
расчёт должен делать backend по политике объекта.

## Что делаем
При запросе отмены backend считает возврат по политике объекта (flexible / strict), моменту отмены и тому, кто
отменяет; результат — сумма, валюта и разбивка (что удержано и почему).

| Политика | Когда отменяют | Гостю |
|---|---|---|
| flexible | ≥ 24 ч до check-in | 100 % |
| flexible | < 24 ч | минус первая ночь |
| strict | ≥ 7 дней | 50 % |
| strict | < 7 дней | 0 % |
| любая | отменяет хост | 100 % |

Сервисный сбор не возвращается никогда. Сумма публикуется в событии `booking.cancelled` — его потребляют
realtime и воркер возврата.

## Не входит
- Сам возврат денег через провайдера — следующая задача эпика.

## Критерии готовности
- [ ] Acceptance-сценарии на все 5 правил (UC-020…UC-024) зелёные.
- [ ] Сумма в событии совпадает с суммой в ответе `POST /api/bookings/{id}/cancel`.
- [ ] Разбивка объясняет каждое удержание (ночь, сервисный сбор), в том числе при возврате 0 %.
