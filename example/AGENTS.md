# Bookly — инструкции агента (точка входа)

Корень проекта — `bookly/`. Корень и `workspace/` — **личный слой**: инструкции, знания, трекер, скрипты (локальный
git, `.gitignore` — белый список). Репозитории сервисов лежат рядом как папки со своим git и **в этот git не входят**.
Пути в слое — от корня проекта целиком; внутри сервиса его `AGENTS.md` считает пути от корня сервиса.

## О продукте
Bookly — площадка бронирования жилья: **хост** публикует объект и календарь, **гость** ищет, бронирует и платит,
обе стороны получают уведомления в реальном времени. Ключевые сущности: Listing, Booking, Payment, Review.
Бизнес-правила — `workspace/docs/knowledgebase/`.

**Стек:** PHP 8.3 / Symfony 7.1 (backend), React 19 / TypeScript (frontend), Node 22 (realtime), PostgreSQL, Redis,
RabbitMQ; всё в docker compose из `infra/`. Связи: frontend → backend по HTTP/JSON; backend публикует события
`booking.*` в RabbitMQ и Redis pub/sub; realtime отдаёт их по WebSocket; auth — JWT RS256 от backend, ключ в
`infra/keys/`. Контракты событий — `workspace/docs/contracts/`.

**Текущий этап и приоритеты** — в трекере команды (очередь BOOK); сюда историю и текущий этап не писать.

## Как работать
Смотреть на тип запроса, а не на один сценарий:
- **Изменение кода или поведения** — только через трекер: `/next-task BOOK-NNN` (подтянуть тикет, сделать, сдать;
  начатую — продолжить). Правила трекера — `workspace/tracker/AGENTS.md`; перед кодом — `<сервис>/AGENTS.md`, затем
  его карта техдоков (файл темы по одному, не всё подряд).
- **Ресёрч, обсуждение, правка знаний** — задачу не заводить: читать и править `workspace/docs/` по индексу
  `workspace/docs/README.md` (матрица «что изменилось → куда писать»).
- **Новая задача** — `/tracker-add`; **заметки, предложения, трение и разбор находок** — `/refine [текст]`;
  **проверки слоя** — `workspace/bin/check/all.sh` (их же гоняет хук pre-commit).
- **Удалённый трекер** — подтянуть тикет `/tracker-pull <KEY>`, комментарий `/tracker-comment <ID> <текст>`, описание
  в трекер `/task-description <ID>`.
- **Замечания к MR** — `/fix-mr`. **Оценка задачи** — `/estimate <ID>` (только по явной просьбе).
Читать по потребности запроса, а не всё сразу.

## Правила
- **Архитектуру, границы и контракты решает команда** там, где она их принимает (RFC в `backend/docs/rfc/`); здесь —
  только ссылка на итог и правило для агента, если оно из этого следует. Спорное — `workspace/tracker/proposals/`
  или вопрос, не молчаливое решение в коде.
- **Инструкции и доки команды** (`<сервис>/AGENTS.md`, `CLAUDE.md`, `docs/`) **не редактировать** без задачи на это;
  мои переопределения и грабли — `<сервис>/CLAUDE.local.md` (не в git сервиса). Ни один файл в сервисах не ссылается
  на этот слой — у команды его нет. `backend/CONTRIBUTING.md` устарел (host-PHP, Symfony 5) — игнорировать.
- **Тело задачи уезжает в трекер:** в постановке и комментариях — ни путей к локальным файлам, ни имён из этого слоя;
  другие задачи — по ключу, доки — по названию. Локальное (`implementation.md`, `context/`) — только в `INDEX.md`.
- **Термины — стандартные.** Задача, решение, проверка; словарь домена — `workspace/docs/knowledgebase/`.
- **Трение называть, а не молчать:** файл в `workspace/tracker/friction/` тогда, когда заметил, и поле «трение» в
  отчёте задачи (порог и формат — `workspace/tracker/AGENTS.md`, «Входящие»). Нечего назвать — «трение: нет».
- **Рабочий каталог оболочки плывёт между вызовами:** `cd` — только в подоболочке, любой `git`, скрипт и путь —
  через `git -C` или абсолютный путь.
- **Пути в бэктиках — от корня проекта целиком**; markdown-ссылка — от корня или от папки файла. Проверяет
  `workspace/bin/check/links.sh`.
- **Перед коммитом — спросить**, показав план по репо (`git -C backend …`; Conventional Commits `feat(BOOK-432): …`);
  статус задачи, код и доки — в одном изменении. `git push` и MR — только по явной просьбе; подагентам передавать
  запрет push.
- Инфраструктурные правки (compose, nginx, `.env`) — в `infra/`, не в сервисах. Ничего на stage/prod без явной
  просьбы; платёжный провайдер локально — только sandbox.
- Секреты — только через переменные окружения (`.mcp.json` использует `${BOOKLY_TRACKER_TOKEN}`).
- `project.yaml` — данные для скриптов `workspace/bin`; агент читает его только через скрипты.
- Знания — в `workspace/docs/`; истина по поведению — код. Память агента — только датированные снимки и факты о
  коде, которых нет в доках; воспроизводимые правила — сюда или в `<сервис>/CLAUDE.local.md`.

## Карта проекта
| Путь | Что | Природа |
|---|---|---|
| `AGENTS.md` | этот файл: базовые правила и карта | инструкции |
| `project.yaml` | данные для скриптов `workspace/bin` (репо, команды качества, префикс, профиль) | инструментарий |
| `backend/` | REST API, домен (listings, bookings, payments), воркеры — свой git (база `main`); инструкции — `backend/AGENTS.md`, мои грабли — `backend/CLAUDE.local.md` | код |
| `frontend/` | веб-приложение гостя и хоста; инструкции — `frontend/AGENTS.md` | код |
| `realtime/` | WebSocket-уведомления (в работе); инструкции — `realtime/AGENTS.md` | код |
| `infra/` | локальный стек и деплой; **инфра-правки только здесь**; `make up`, адреса в `workspace/docs/dev/README.md` | код |
| `workspace/docs/` | знания: концепция — ссылки на доки команды, `knowledgebase/` (правила, UC), `contracts/` (события), `dev/` (стек); индекс — `workspace/docs/README.md` | вневременное |
| `workspace/tracker/` | зеркало задач трекера и работа над ними, входящие (`notes/`, `proposals/`, `friction/`); правила — `workspace/tracker/AGENTS.md` | временное |
| `workspace/prompts/` | тела промптов для `.claude/commands/*` | инструментарий |
| `workspace/bin/` | скрипты (`workspace/bin/README.md`): трекер `trk.sh`, проверки слоя `all.sh`, команды качества `cmd.sh <команда> [repo]`, `healthcheck.sh`, статус репо `status.sh`; звать абсолютным путём | инструментарий |
| `workspace/memory/` | память агента | только факты о коде и датированные снимки |
| `.claude/` | команды-шимы, настройки; личный слой и хуки — `.claude/README.md` | инструментарий |
| `agent-workspace-template/`, `local/` | клон шаблона слоя; личные скрипты, заметки, дампы | не в git |

Поисковые инструменты уважают `.gitignore`; папки сервисов возвращает в поиск корневой `.ignore` — не удалять; новый
сервис — строка `!/<путь>/` (проверка — `workspace/bin/check/searchignore.sh`).
