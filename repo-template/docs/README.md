# docs/ — техдоки {{SERVICE}}: карта и правила ведения
Зачем: контекст для агента перед правкой кода — то, чего не видно из кода за минуту: инварианты, контракты, «почему
так», точки расширения. Правила продукта и решения о границах — в слое знаний проекта (у команды — её доки); здесь —
как принятое реализовано в коде и что нельзя сломать.

## Карта
Третий столбец — триггер: изменился такой файл, значит техдок темы правится в том же коммите. Из этой таблицы
`scripts/check-docs.sh` берёт правила гейта (`|` внутри regex пишется как `\|`) — правь карту, а не скрипт.

| Файл | О чём | Правится вместе с |
|---|---|---|
| `architecture.md` | модули (роли и разрешённые зависимости), что где живёт, поток данных, сквозные точки расширения; читать первым | `{{src/[a-z]+/mod\.rs\|composer\.json}}` |
| `{{тема}}.md` | {{инварианты и контракты темы}} | `{{src/(auth\|token)/.*}}` |
| `history.md` | что появилось в какой задаче, строка на задачу; искать `grep {{PREFIX}}-NNNN` | `{{src/.*}}` |
| `decisions.md` | журнал техрешений внутри границ: что выбрано, почему, что отвергнуто | — |

Порядок для типовой задачи: эта таблица → `architecture.md` → файл темы. Не читать всё подряд.

## Правила ведения
**Что писать**
- Инвариант или контракт, который компилятор не проверяет: порядок полей, порядок обработки, кто владеет состоянием.
- «Почему так»: выбор библиотеки, алгоритма, параметра — с причиной и отвергнутой альтернативой. Одна строка
  в `decisions.md`.
- Грабли, на которых уже спотыкались: версии, платформа, шум замеров.
- Точка расширения: как добавить модуль, сущность, команду, не сломав границы.

**Что не писать**
- То, что видно из кода: сигнатуры, перечни полей и методов — это doc-комментарий в коде. Из типа в техдоке
  называется только то, у чего есть контракт: порядок, владение, что производное.
- Ход работы, планы, журнал — трекер. Цифры замеров — их журнал в слое знаний.
- Правила продукта и решения о границах — слой знаний проекта; здесь только ссылка.
- «Сделаем в задаче NNN» как содержание. Указатель на будущий док — одной строкой, не больше.
- То, что уже написано в соседнем файле: у каждого факта один владелец, остальные ссылаются по имени файла.

**Как**
- Одна тема — один файл, до ~120 строк. Вырос — разделить и добавить строку в карту. Новая тема — новый файл
  плюс строка в карте, в одном коммите с кодом. `decisions.md` и `history.md` — журналы, растут по строке на задачу.
- Текущее состояние, не история: устарело — переписать, а не дописать «теперь». Расходится с кодом — верить
  коду и править док. Шапка файла темы без «Статус: задача…»: кто что принёс — `history.md`.
- `decisions.md` — единственный append-only файл. Отменённое решение не стирается: пометка `[отменено NNN]`
  в начале строки и новая строка со ссылкой на старую.
- Таблица — для коротких ячеек; строка длиннее ~300 знаков — подраздел со списком.
- Ссылка на файл рядом — просто имя в бэктиках (`architecture.md`); ссылок на личный слой агента в tracked-файлах нет.
- Триггер правки — третий столбец карты; проверяет `scripts/check-docs.sh`.
